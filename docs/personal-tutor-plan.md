# 개인 맞춤 영어 선생님: 제품 기준

이 문서는 사용자의 새 목표를 구현 기준으로 정리한다. 핵심 결과는 **매일 정한 시간에 시작 → 어제와 이전에 틀린 표현을 떠올려 말하기 → 실제 발화에 근거한 구체적 피드백 → 다음 복습 시점 예약**이다. 단어 학습은 매일의 기본이고, 문장 이해·생성·말하기가 그 단어를 실제로 쓰게 만드는 경로다.

## 현재 확인된 구현

| 능력 | 현재 근거 | 한계 |
| --- | --- | --- |
| CEFR 시작점 | A1–C2 어휘 선택 24문항, 난이도 섞기와 답 위치 균형 | 어휘 인지만 측정한다. 종합 CEFR·IELTS 점수가 아니다. |
| 단어 복습 | Stage 0–5, KST 날짜, 첫 답안만 점수 반영, 오답 재출제 | 간격은 고정된 1/3/7/14/30/60일 표다. 개인별 망각 확률을 추정하지 않는다. |
| 비즈니스 레지스터 | 54개 원본 항목의 구어체·문어체 예문과 한국어 차이 설명 | 사용자 업종·역할별 선택과 문장 생성 복습은 없다. |
| 말하기 | 음성 인식 → AI 대화 → 종료 후 교정·다음 과제; 최근 오답과 교정을 프롬프트에 제공 | Mac mini/Tailscale/모델 키가 없으면 사용 불가. iPhone 실기기와 모델 품질 검증 전. 발음·강세 자체를 채점하지 않는다. |
| 개인화 화면 | 최근 30일 첫 답안의 CEFR·품사별 오답 묶음, 최근 교정 사례 | 표본 5개 미만은 분석 근거가 부족하다. 의미·문법·화용 범주의 오류 분류와 추세는 없다. |
| 학습 시간 | 일일 새 단어 수와 복습 상한 설정 | 선호 시간·요일·리마인더는 없다. |

## 학습자의 하루: 목표 흐름

1. **시작 전:** 선호 학습 시간과 요일, 업무 상황(회의·이메일·고객 응대 등), 하루 가능한 분량을 저장한다. 시간이 되면 인앱 시작 카드에 오늘의 복습 수와 예상 분량을 표시한다. 기기 알림은 별도 권한과 실제 iPhone 검수가 끝나기 전까지 제공한다고 표시하지 않는다.
2. **기억에서 꺼내기:** 밀린 단어·문장을 먼저 제시하고 뜻 보기 → 빈칸 → 자유 문장 순으로 답의 힌트를 줄인다. 같은 문제 재시도는 연습 기회지만 첫 답안만 학습 평가에 반영한다.
3. **문장 많이 보기:** 새 단어마다 자연스러운 문맥 문장, 한국어 뜻, 말로 하는 표현, 이메일·문서 표현을 함께 보여 준다. 정답을 보기 전에 문장 속 의미나 다음 구절을 예상하게 한다. 문장 자체도 별도 복습 항목이 되어 단어와 독립된 만기일을 가진다.
4. **말하기 연습:** 오늘 복습한 단어·문장을 실제 업무 시나리오에서 말한다. AI는 반복 오류 하나를 선택해 후속 질문으로 다시 써 볼 기회를 만든다. 대화 중에는 흐름을 끊지 않고 종료 후 원문·자연스러운 대안·격식체 대안·표현별 뉘앙스·다음 한 문장 과제를 보여 준다.
5. **다음 날 연결:** 틀리거나 힌트를 쓴 항목은 더 빨리, 안정적으로 회상한 항목은 늦게 내며 다음 복습 시점과 이유를 볼 수 있게 한다. 다음 대화에는 지난 교정 한 가지를 다시 가져온다.

## 피드백의 증거와 표현 기준

- AI가 고치는 대상은 사용자의 **실제 전사 문장**이어야 한다. 원문을 보존하고 무엇이 바뀌었는지 표시한다. 전사가 불확실하면 사용자가 텍스트를 확인·수정하도록 한다.
- 자연스러운 표현은 적어도 `대화체`, `격식 있는 문어체`, `다른 말 1–2개`로 구분하고, 서로 완전히 같은 뜻이 아니라면 **어떤 상황에서 바꿔 쓸 수 없는지** 설명한다. 예: “touch base”는 동료 간 가벼운 확인에 어울리고 공식 요청 메일에는 구체적 목적을 쓰는 편이 낫다.
- 동의어는 목록만 나열하지 않는다. 의미 강도, 공손함, 사용 맥락 중 하나 이상을 비교하고 사용자가 한 문장을 다시 쓰도록 연결한다.
- 전사 텍스트만으로 발음·억양·강세가 원어민과 비슷하다고 평가하지 않는다. 그런 피드백을 제공하려면 원음 기반의 별도 음성 평가와 동의·비용·기기 검증이 필요하다. 현재 녹음은 영구 보관하지 않는다.
- 모델이 만든 교정은 정답 단정 대신 근거가 있는 제안으로 보여 주고, 사용자가 “이미 자연스러움/어색함”을 표시할 수 있게 한다. AI 품질 검수 전에는 완전한 정확도를 주장하지 않는다.

## 구현 순서와 합격 기준

| 우선순위 | 작업 | 합격 기준 |
| --- | --- | --- |
| P0 | 선호 시간·요일, 오늘의 학습 카드 | 시간대 KST에서 날짜 경계가 맞고, 알림이 없어도 앱을 열면 해당 시간의 목표가 보인다. |
| P0 | 구조화된 말하기 교정 | 같은 발화에 대해 자연스러운 대안, 격식 대안, 다른 표현과 뉘앙스를 JSON 필드로 저장하고 세션 재진입 후에도 보인다. 무근거 교정은 표시하지 않는다. |
| P0 | 문장 복습 | 단어와 별개인 문장 ID·복습 상태·첫 답안 로그가 있고, 새로고침 후 만기일과 기록이 유지된다. |
| P1 | 개인화 복습 스케줄 | 고정 단계표를 명시적으로 유지하거나 FSRS 등 적응형 방식을 도입한다. 방식을 바꾸면 기존 stage 0–5 이력의 이행·기대 간격 테스트를 먼저 만든다. 어떤 경우에도 “망각곡선 최적화”를 근거 없이 표시하지 않는다. |
| P1 | 업무 상황별 콘텐츠 | 사용자에게 필요한 업종/업무를 선택하게 하고, 같은 뜻의 구어체·문어체 예문을 검수한 뒤 검색·복습·대화 목표로 연결한다. |
| P1 | iPhone 알림 | 설치형 PWA, 사용자 명시적 알림 허용, HTTPS 푸시 구독 및 서버 일정 작업이 실제 iPhone에서 동작해야 완료로 판정한다. 권한 거부·기기 오프라인·시간 변경도 검수한다. |
| 출시 게이트 | Mac mini 운영·음성 품질·비용 | 실기기에서 10턴 이상 연속 대화, iPhone 잠금/앱 전환 복구, 실제 모델 응답 평가, 월 예상액과 공급자 청구액 비교, 백업/복구 리허설을 통과한다. |

## 데이터 모델 제안

단어와 문장을 모두 `review_item`으로 표현하되 `kind: word | sentence`와 원본 콘텐츠 ID를 분리한다. `review_event`에는 첫 답인지 재시도인지, 정답·힌트·응답 시각·모드를 저장한다. `conversation_feedback`은 원문, 교정문, 구어체, 문어체, 대안, 뉘앙스, 해당 발화 ID를 연결한다. `study_schedule`에는 시간대·선호 시각·요일·알림 동의를 저장한다. 현재 SQLite는 앱 전체를 한 JSON 행에 저장하므로 기능 확장 전 스키마 이행·백업 계획이 필요하다. 로컬 단어 기록은 서버와 자동 병합되지 않아 기기 교체 전에 JSON 백업이 필요하다.

실제 알림·AI 품질·기기 동작은 아직 검증되지 않았다. 이 문서의 새 목표는 기존 구현 완료 주장과 분리해 추적한다.
